SEC Ingestion & Indexing Sequence (offline path)

Where evidence_id is born. Section keys are normalized, chunk IDs are deterministic, coverage is asserted through the store — not the parser.

Where the join key is born

  • Step 6 mints chunk_id = f(accession, section_key, chunk_index) — deterministic.
  • That id becomes EvidencePacket.evidence_id at retrieval, the gold-label target at S2, and the citation key at memo time.
  • Re-ingest the same filing → identical ids (the S1-T02 idempotency test).

Coverage is asserted at the store, not the parser

  • Step 11 counts critical-section chunks through the retrieval interface, so it catches "parsed fine but never indexed" bugs.
  • Missing optional section → explicit skip/xfail with reason, never a silent pass.
  • This is the regression lock that retires the old MSFT/NVDA zero-section failure for good.

One parse, two consumers

  • The parser output feeds both the live index (steps 5–9) and the offline source-section cache (the note).
  • Same parser = the benchmark validates anchors against exactly what the system ingested.
  • No live SEC calls in CI; the cache is committed and deterministic.
